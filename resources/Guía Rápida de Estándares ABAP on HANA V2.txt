1. Objetivo  
Dar una guía de los estándares de Desarrollo que conlleven a un orden y una estructura clara, organizada y homogénea de los  desarrollos en las diversas plataformas ABAP.  
2. Alcance  
Este documento da un resumen de las convenciones de nombres para los diversos objetos en ABAP. En todas las plataformas  ABAP (AFS, APO, BW, POSDM, etc) de Crystal se debe cumplir con el estándar.  
RICEFWnnnnn: Identificador generado por el equipo de arquitectura de Crystal. Este identificador empieza por la inicial del  RICEFW seguido de un consecutivo de 5 digitos. Ej. R1000  
3. Convenciones para Nombres  
Ordenes de transporte:  
XX-AA-RICEFW DESCRIPCION #001 
XX = DV(Desarrollo) CT(Configuracion)  
AA = Modulo. Ej. SD  
Ordenes de transporte Copia:  
TC-[NUMERO(s) ORDEN ORIGINAL]

14. Manejo de Log  
13.1. Log de Aplicación  
Para el manejo de Log de aplicaciones se creo la clase ZCLCXR1002_LOG_APLICACION mediante la cual se busca recopilar  todos los eventos de un proceso y escribirlo en base de datos si es del caso.  
Para su uso, consultar la documentación generada mediante ABAPDoc.  
13.2. Log de Auditoria para tablas Z  
Para el manejo de este log se tiene creada la clase abstracta ZCLCXR1000_LOG_AUDITORIA. 
En esta clase se tiene un método abstracto llamado REGISTRAR_LOG el cual debe ser redefinido al momento de su  implementación.  
Procedimiento:  
- Creación del log de modificación por la transacción SCDO (Revisar estándar para el nombramiento).  
Ejemplo: ZCX_ZTCXR1000_1 Log de Modificaciones tabla ZTCXR1000_1  
- Crear una clase por cada tabla Z a la cual se le piense manejar el log de auditoria. Esta clase debe heredar de la clase  ZCLCXR1000_LOG_AUDITORIA para poder realizar la redefinición del método REGISTRAR_LOG. Dentro de este método se  implementa la lógica para que registre la información del log de la tabla Z.  
Ejemplo: Tabla ZTCXR1000_1 (Parámetros desarrollos SAP-ABAP)  
Clase: ZCLCXR1000_LOG_ZTCXR1000_1
